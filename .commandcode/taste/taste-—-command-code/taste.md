# Taste — Command Code
- Communicates in Indonesian (Bahasa Indonesia). Assistant responses should match, mixing Indonesian with English technical terms where natural. Confidence: 0.8
- Prefers minimal, scoped edits that match the request literally — do not expand changes to unrelated sections (e.g. Hero, Contact, site-wide CTAs) when only project-card actions were asked for. Confidence: 0.8
- Prefers comprehensive light/dark theme switching: when background flips white→black (or vice versa), fonts and UI objects should follow (white↔black inversion), but accent/brand colors (blue, yellow, etc.) must remain unchanged — only grayscale tones participate in the theme flip. Confidence: 0.8
- When temporarily disabling a project or feature without deleting it, replace primary action buttons (e.g. Live Demo) with a disabled "Sedang Maintenance" control and keep secondary/source links (e.g. GitHub) intact and clickable. Confidence: 0.85
- When using Tailwind v3 with CSS-variable-based theme tokens (e.g. `--cyber-bg`, `--cyber-fg`), do NOT use `@apply bg-cyber-bg text-cyber-fg` in CSS files — Tailwind v3 cannot resolve class names backed by CSS variables inside `@apply`, which breaks the build with `class does not exist` errors. Instead, use direct CSS properties on selectors (e.g. `background-color: rgb(var(--cyber-bg)); color: rgb(var(--cyber-fg));`). Keep the variable-backed utility classes in JSX where they work fine. Confidence: 0.85
- Values GSAP scroll-triggered animations and prefers to keep them. When GSAP animations break (e.g. cards not appearing, paths rendering incorrectly), the preference is to fix the root cause — typically an initialization timing issue — rather than remove the animations and fall back to static rendering. Key fix pattern: gate `scrollEnabled` / ScrollTrigger initialization behind `appReady` (AppReadyContext) so animations only activate after the loading screen completes and DOM dimensions are correctly measured. Confidence: 0.85
